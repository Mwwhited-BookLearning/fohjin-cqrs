# Supporting research

Each doc here was written *at the point a technology choice was made*, not after the fact —
these are decision records, not retrospectives. If you're wondering "why OpenIddict and not
Duende" or "why Aspire," this is where that reasoning actually lives; `../00-architecture-overview.md`
only links to these, it doesn't repeat the reasoning.

| Doc | Decision it records |
|---|---|
| [`oidc-sts-openiddict-vs-duende.md`](oidc-sts-openiddict-vs-duende.md) | Why `Fohjin.DDD.Sts` is built on OpenIddict rather than Duende IdentityServer |
| [`rfc10008-http-query-method.md`](rfc10008-http-query-method.md) | Why `Fohjin.DDD.WebApi` uses the (real, IETF-standard) HTTP `QUERY` method for OData-style filtering instead of only `GET` query strings |
| [`asyncapi-saunter.md`](asyncapi-saunter.md) | Why the `GET /api/events` SSE stream is documented as AsyncAPI, and why Saunter generates it |
| [`nswag-client-codegen.md`](nswag-client-codegen.md) | Why both the WinForms C# client and the Vue TypeScript client are generated by NSwag from the same OpenAPI document, rather than hand-written |
| [`hosting-aspire-docker-compose.md`](hosting-aspire-docker-compose.md) | Why local orchestration is .NET Aspire, with Docker Compose as a *generated* deployment artifact rather than a hand-maintained one |
